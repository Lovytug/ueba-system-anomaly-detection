# ueba-system-anomaly-detection

# Программный пакет обнаружения аномалий

Программный макет запускается из командной строки и предоставляет три основных режима работы:
1) train - сбор обучающей выборки и обучение модели;
2) detect - обнаружение аномалий в заранее подготовленном наборе данных;
3) online - непрерывная детекция аномальной активности в реальном времени.

Все результаты работы программы автоматически сохраняются в каталоге `results/`.

## 1. Использование программного пакета

### 1.1 Подготовка
Перед запуском необходимо проверить и при необходимости установить зависимости, а также активировать окружение Python командой:

```bash
pip install -r requirements.txt
```

Запуск выполняется из корневого каталога проекта:

```bash
python main.py <режим> [параметры]
```

Для просмотра доступных режимов и параметров:

```bash
python main.py --help
```

### 1.2 Сбор данных и обучение модели
Для сбора данных с собственного ПК используется режим `train --collect`:

```bash
python main.py train --collect --samples 1000 --interval 5 --epochs 50
```

В данном случае программа собирает 1000 системных наблюдений с шагом 5 секунд, формирует обучающую выборку в реальном времени, выполняет предварительную обработку признаков и обучает модель на собственных данных в течение 50 эпох. После завершения модель сохраняется в папку результатов.

Результат запуска сохраняется в отдельном каталоге по структуре: `result/год-месяц-дата/часы-минуты-секунды/файлы`.

### 1.3 Обучение на существующей выборке
Если обучающая выборка уже сформирована заранее, можно применить ее для обучения модели без повторного сбора:

```bash
python main.py train --train-path "путь к датасету" --epochs 50
```

Датасет, который был применен для обучения, будет продублирован в папку результатов.

### 1.4 Пакетное обнаружение аномалий
При наличии готовой модели и набора данных для детекции используется режим `detect`:

```bash
python main.py detect --data "путь к датасету" --model "путь к модели.joblib"
```

Данный режим подразумевает единоразовое определение аномалий без онлайн-работы. Результаты сохраняются в каталоге `results/`:
*   Файл `inference.csv` отражает результаты съема показаний ПК.
*   Файл `report.json` содержит результат детекции.

### 1.5 Онлайн детекция
Для непрерывного анализа поведения компьютера используется режим `online`:

```bash
python main.py online --model "путь к модели.joblib" --interval 5
```

Программа начинает работать циклически с интервалом 5 секунд. Данные в онлайн-времени записываются в файл `inference.csv`, а результат детекции и признаков записывается в `report.json`.

## 2. Архитектура программного макета

### 2.1 Графический вид
Общая схема работы представлена на Рисунке 1 (функциональный график программного макета).
<img width="974" height="582" alt="image" src="https://github.com/user-attachments/assets/fdb223fa-c8b9-48d6-a91f-3a36778232a5" />

**Обозначения на схеме:**
1) Зеленые ячейки - точки входа и выхода программы.
2) Фиолетовые ячейки - основные функциональные блоки, присутствующие в режимах «обучение» и «инференс».
3) Красные ячейки - функциональные блоки, предназначенные только для режима «обучение». При инференсе данные блоки не задействуются.
4) Стрелочки демонстрируют порядок перехода данных. Фиолетовые показывают направление работы при инференсе, красные - при обучении.

При работе в режиме инференса красные блоки исключаются из потока. При обучении данные идут строго по направлению красных стрелочек через красные блоки, после чего переходят к фиолетовым блокам.

### 2.2 Описание блоков
Назначение каждого блока:

1) **DataCollector** - сборщик данных с потребительского ПК в реальном времени.
2) **DataCleaner** - блок обработки ошибок и пропусков датасета.
3) **ArtifactDetector** - блок обработки экстремально больших значений (работает только на этапе обучения).
4) **FeaturesEngineer** - блок обработки features engineering, включающий изменение распределения, отбор колонок и создание новых признаков.
5) **ScaleManager** - функциональный блок, применяющий механизмы масштабирования к соответствующим признакам.
6) **AutoEncoder** - модель машинного обучения типа автоэнкодер.
7) **EvalRisk** - часть блока AnomalyDetector, отвечающая за алгоритм расчета риска для объекта.
8) **Classification** - часть блока AnomalyDetector, отвечающая за классификацию величины риска как аномальной или нормальной.
9) **EvalParameters** - часть блока AnomalyDetector, отвечающая за расчет параметров алгоритма оценки риска (работает только на этапе обучения).

С детальной работой классов можно ознакомиться в Приложении А.

## 3. Практическая часть

Программный пакет применяется для обнаружения аномалий в реальном времени. Модель обучается на готовом датасете, сформированном при непрерывной работе ПК за 24 часа. Данный набор данных является нормальным поведением пользователя. Для корректной работы модели и вылавливания цикличного паттерна поведения рекомендуется использовать данные за двое суток, однако чувствительность детекции в реальном времени допустима и при суточных данных.

Итоговая исходная обученная модель хранится по пути `./results/2026-08-08/17-44-26`. Там же хранится датасет, на котором обучалась модель. Снятые результаты работы в реальном времени хранятся по пути `./results/2026-08-08/17-47-36`.

Модель, которая применялась для обучения, всегда дублируется в папках результатов для воспроизведения экспериментов.
